SPENDWISE — MASTER DEVELOPMENT PROMPT

1. YOUR ROLE

You are a senior full-stack web developer and software architect.

Your task is to build a complete, functional personal finance web application called SpendWise.

The application must be designed specifically for Google Apps Script and must use:

* Google Apps Script as the backend
* HTML, CSS and JavaScript for the frontend
* Google Sheets as the database
* Google Drive for receipt/file storage

This is a real portfolio project, not a simple demonstration.

Do not create a fake interface that only looks functional.

Features such as login, saving transactions, editing transactions, budgets, accounts and reports must actually work.

⸻

2. IMPORTANT DEVELOPMENT RULES

Follow these rules throughout the entire project.

Rule 1 — Build a real application

Do not create buttons that do nothing.

Every visible button must either:

* perform its intended action,
* open the correct page,
* open a dialog,
* save information,
* update information,
* delete information,
* or clearly display that the feature is not available yet.

Do not leave fake functionality in the finished Version 1.

Rule 2 — Real data storage

All user financial information must be saved to Google Sheets.

Do not store important financial information only in:

* JavaScript variables
* browser localStorage
* temporary arrays
* session-only variables

LocalStorage may only be used for non-critical interface preferences such as theme selection.

Rule 3 — User privacy

Every user’s financial data must be associated with their unique user ID.

Users must only be able to access their own:

* accounts
* transactions
* budgets
* savings goals
* receipts
* notifications
* settings

Never return another user’s financial data.

Rule 4 — Do not use fake data in production

You may use sample data during development.

However, the finished application must use the real Google Sheets database.

Clearly separate demo/sample data from real user data.

Rule 5 — Mobile first

The application must work properly on:

* iPhone-sized screens
* Android-sized screens
* tablets
* laptops
* desktop computers

Do not simply shrink the desktop layout.

Create a proper responsive layout.

Rule 6 — Do not redesign unnecessarily

Follow the design specification below.

Do not replace the requested design with a generic AI-generated dashboard.

The interface should feel like a carefully designed financial application.

Rule 7 — Keep code organized

Do not place the entire application inside one enormous file.

Separate backend logic and frontend logic into logical files.

Rule 8 — Explain important setup steps

After generating the code, clearly explain:

1. Which files must be created.
2. Where each code block belongs.
3. Which Google Sheet must be created.
4. Which Google Drive folder must be created.
5. Which Script Properties must be configured.
6. How to deploy the application.
7. How to test the application.

Use simple language.

⸻

3. PROJECT PURPOSE

SpendWise is a personal finance management application.

The main purpose is to help users:

* track income
* track expenses
* manage multiple money accounts
* create budgets
* track savings goals
* understand spending habits
* view useful financial reports
* store receipts
* receive financial reminders

The application should feel like a modern banking/finance application rather than a generic spreadsheet.

16. ACCOUNT BALANCES

When adding an expense:

Account balance decreases.

When adding income:

Account balance increases.

When transferring:

Source account decreases.

Destination account increases.

A transfer must not affect total net income/expense.

Editing or deleting a transaction must correctly reverse the previous balance change before applying the new change.

This is extremely important.

26. RECEIPT STORAGE

When a user uploads a receipt:

1. Validate file type.
2. Validate reasonable file size.
3. Upload to the configured Google Drive folder.
4. Generate a receipt ID.
5. Save metadata to the Receipts sheet.
6. Link the receipt to the transaction.
7. Allow the user to view the receipt later.

If upload fails, do not create a broken receipt record.
